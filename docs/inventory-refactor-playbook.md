## Cil
Jednotny provozni postup, aby dokumentace, audit softwaru a audit kodu zustaly v jednom kontextu.

## Denni provoz (automat)
1. V 15:00 se spusti `scripts/inventory_project_sw.ps1` (Windows Scheduler).
2. Vygeneruji se:
- `docs/software-inventory.md`
- `logs/software-inventory.json`
- `logs/software-audit-last.txt`
3. Kriticke kontroly musi byt bez FAIL.

## Tydenni refactoring dokumentace
1. Spustit audit manualne a overit vystupy.
2. Opravit nesoulad dokumentace vs. realny stav kodu a konfigurace.
3. Projit dead links, metadata, duplicity a stale sekce.
4. Zapsat zmeny do ridicich dokumentu (`INDEX.md`, `GOVERNANCE.md`, pripadne `CONSTITUTION.md`).

## Povinne kontroly pred vetsi zmenou
- Software inventura: aktualni a bez kritickych failu.
- Run on Save health check: PASS.
- Audit hotoveho kodu: lint/test/security dle stacku (Rust + Node + docs).
- Dokumentace musi reflektovat realne API, workflow a skripty.
